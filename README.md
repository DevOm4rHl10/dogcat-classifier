# Meowf Investigations

*Dog or cat? A CNN classifier that shows its evidence (Grad-CAM).*

A convolutional neural network, built and trained from scratch in PyTorch, that
classifies a photo as a dog or a cat. It is served through a small Flask web app.
Every prediction comes with a **Grad-CAM heatmap** showing which regions of the image
drove the decision, and a slider to compare the heatmap with the original photo.
Photos that show neither animal are caught first by a pretrained ImageNet model, and a
separate page shows the model's test results.


---

## Highlights

- **CNN from scratch** in PyTorch: three convolutional blocks and a fully connected head,
  trained with binary cross-entropy on the Kaggle Dogs vs. Cats dataset.
- **Explainability with Grad-CAM**, implemented by hand: gradients of the predicted
  class's logit with respect to the last convolutional feature maps weight those maps,
  producing a heatmap of the evidence behind each decision.
- **"Neither" detection**: a pretrained MobileNetV3 (ImageNet) gatekeeper turns away photos
  with no dog or cat, because a two-class model is confidently wrong on them (a trash bag
  scored 97% "dog"). Visitors can still force a classification to see that failure.
- **Test-results page** (`/metrics`): confusion matrix, precision / recall / F1, ROC curve,
  a calibration chart and the most confident mistakes, generated by `metrics.py`.
- **A visual identity of its own**: the site is a detective's case file. Inspector GRADget,
  an original basset-hound character whose name is a nod to Grad-CAM, examines each photo; the heatmap is
  rendered as red ink on a sepia evidence print, the verdict is a rubber stamp, photos that
  aren't pets are "not a suspect", and the test results are the "case archive".
- **Fast on mobile**: photos are resized in the browser to 512 px before upload,
  so a 5 MB phone photo is sent as roughly 60 KB. No CSS framework; the illustration is
  inline SVG; two small typewriter web fonts.
- **PyTorch-free serving**: the models are exported to ONNX and served with ONNX Runtime.
  Grad-CAM needs gradients, which ONNX Runtime doesn't provide, so the classifier head and
  its backward pass are written out in NumPy (checked against PyTorch autograd and finite
  differences). The app runs in about 200 MB of memory, so it fits a free 512 MB server.
- **Production setup**: Gunicorn with the models loaded once at start-up, a slim Docker
  image, upload size limits, input validation and a `/health` endpoint.

## Results

Measured on 4,960 held-out test photos that the model never saw during training or tuning
(details in *Leakage check* below):

| Metric | Score |
|--------|-------|
| **Accuracy** | **81.5 %** |
| **F1 score (overall, averaged over both classes)** | **0.815** |
| ROC AUC | 0.894 |

![Confusion matrix on the clean test set: 2,053 cats and 1,989 dogs correct; 422 cats called dog, 496 dogs called cat](docs/confusion_matrix.png)

Per class:

| Class | Precision | Recall | F1    | Photos |
|-------|-----------|--------|-------|--------|
| Cat   | 0.805     | 0.830  | 0.817 | 2,475  |
| Dog   | 0.825     | 0.800  | 0.812 | 2,485  |

The model mislabels dogs as cats (496 false negatives, treating "dog" as positive) slightly
more often than cats as dogs (422 false positives). The full report, with an ROC curve, a
calibration chart and the most confident mistakes, is at `/metrics` in the app.

**Leakage check** (`scripts/check_leakage.py`): no file appears in two splits. The
Kaggle dataset itself contains a few repeated photos under different numbers (one is even
filed as both a cat and a dog), so 42 test photos (0.8%) that were byte-identical or
perceptually near-identical to a training or validation photo were removed. Accuracy on the
full 5,002 was 81.5% too, so the duplicates had no meaningful effect.

## How it works

1. **Data split**: `labelling/split.py` validates every image, removes exact
   duplicates, and makes a reproducible, stratified 60 / 20 / 20 train / validation /
   test split.
2. **Training**: `classifier.py` trains the CNN on `data/train` for 15 epochs with
   Adam (lr 1e-3, batch size 32), reporting validation loss and accuracy each epoch.
3. **Evaluation**: `metrics.py` computes the confusion matrix, per-class precision,
   recall and F1, ROC AUC, calibration, and the gatekeeper's false-rejection rate on
   `data/test`, and writes them to `static/metrics/` for the results page.
4. **Gatekeeper**: MobileNetV3-Small adds up its probabilities for the 118 dog-breed and
   5 domestic-cat ImageNet classes. Below 0.2 (configurable), the photo is labelled "neither".
5. **Inference**: the uploaded image is rotated upright (EXIF), converted to RGB,
   resized to 128 × 128 and scaled to [0, 1], exactly as during training.
6. **Grad-CAM**: one forward and one backward pass give both the prediction and
   the heatmap. The strongest evidence is drawn in red ink over a sepia print of the photo.

### Architecture

```
Input 3 × 128 × 128
→ Conv 3×3 (32)  → ReLU → MaxPool 2×2      →  32 × 64 × 64
→ Conv 3×3 (64)  → ReLU → MaxPool 2×2      →  64 × 32 × 32
→ Conv 3×3 (128) → ReLU → MaxPool 2×2      → 128 × 16 × 16   (Grad-CAM taps conv3, before pooling)
→ Flatten → Linear 32,768 → 512 → ReLU → Dropout 0.5
→ Linear 512 → 1 (logit; sigmoid > 0.5 = dog)
```

About 16.9 M parameters, 99 % of them in the first fully connected layer.

## Run locally

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-train.txt
python scripts/download_gatekeeper.py   # once: saves the MobileNetV3 weights
python scripts/export_onnx.py           # once: exports the models the app serves
flask --app app run --debug              # http://127.0.0.1:5000
```

### Reproduce training

Download the [Kaggle Dogs vs. Cats](https://www.kaggle.com/c/dogs-vs-cats) images into
`training-data/Cat` and `training-data/Dog`, then:

```bash
python labelling/split.py     # build data/train, data/val, data/test
python classifier.py          # train, saves saved_models/dogcat_cnn.pth
python metrics.py             # evaluate on the test set, results at /metrics
```

## Deploy

The live demo runs on [Render](https://render.com)'s free tier (512 MB of memory, no card
needed) from the `Dockerfile`:

```bash
docker build -t meowf .
docker run -p 8000:8000 meowf     # http://localhost:8000
```

- **Why ONNX:** PyTorch alone takes ~300 MB of memory, so the PyTorch version of this app
  didn't fit in 512 MB. The ONNX Runtime version uses ~200 MB and starts in seconds.
- **Staying awake:** free Render services sleep after 15 minutes without traffic and take
  about a minute to wake. A free uptime monitor requests `/health` every 10 minutes, so
  visitors don't wait.
- The container reads the `PORT` environment variable, so the same image runs on any host
  that deploys a Dockerfile.

## Limitations

- **Overconfident outside its training data**: on its own, the CNN gave a trash bag 97%
  "dog" and a person 97% "cat". The gatekeeper handles this, at the cost of an extra
  model; how well it rejects non-pets isn't measured yet (no non-pet test set).
- **One animal per photo**: images with both a dog and a cat have no correct label.
- **No augmentation or pretrained backbone**: accuracy is well below what transfer
  learning (e.g. a fine-tuned ResNet) reaches on this dataset. See *Next steps*.

## Next steps

- Data augmentation (random crops, flips, colour jitter) and ImageNet normalisation.
- Keep the checkpoint with the best validation loss, with early stopping.
- Replace `Flatten → Linear(32,768, 512)` with global average pooling to cut the
  parameter count by ~99 % and reduce overfitting.
- Compare against a fine-tuned pretrained model (ResNet-18 / EfficientNet-B0).
- Build a small non-pet test set to measure how well the gatekeeper rejects "neither" photos.
